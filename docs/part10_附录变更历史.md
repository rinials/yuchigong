### A.1 沉浸式远程协作

| 项目 | 描述 |
|-----|------|
| **用例名称** | 沉浸式远程协作 |
| **用例编号** | UC-5.1.2-001 |
| **所属用例族** | 沉浸式通信 |
| **描述** | 分布在全球各地的团队成员通过6G网络在共享虚拟空间中进行实时三维协作 |
| **参与者** | 远程协作者（多人）、网络运营商、XR平台提供商 |
| **前提条件** | 所有参与者配备XR终端设备；网络提供超低时延和超高带宽连接 |
| **服务流程** | 1. 发起协作会话 → 2. 网络建立多方连接 → 3. 终端采集三维和音频数据 → 4. 数据实时传输和同步 → 5. 各端渲染共享虚拟空间 → 6. 支持实时交互和文件共享 |
| **后置条件** | 协作内容可保存和回放 |
| **数据速率需求** | ≥ 100 Gbps |
| **时延需求** | < 1 ms |
| **可靠性需求** | 99.999% |

| **服务流程** | 1. 监测到网络异常或需求变化 → 2. AI代理互相通信和协商 → 3. 制定优化方案 → 4. 执行资源调整 → 5. 验证效果并反馈 |
| **后置条件** | 网络性能优化完成，日志记录供审计 |
| **数据速率需求** | 高（取决于AI模型复杂度） |
| **时延需求** | < 10 ms |

### A.3 网络请求的车辆服务功能执行

| **用例编号** | UC-5.8.2-002 |
| **所属用例族** | 车联网服务 |
| **描述** | 网络根据道路状况和交通管理策略，主动请求车辆执行特定服务功能 |
| **参与者** | 6G网络、车辆（自动驾驶系统）、交通管理中心 |
| **前提条件** | 车辆支持网络发起的服务请求协议；网络已获取实时道路状况信息 |
| **服务流程** | 1. 网络检测到交通状况变化 → 2. 交通管理策略评估 → 3. 向相关车辆发送服务请求 → 4. 车辆执行请求（如减速、变道、停车） → 5. 执行结果反馈至网络 |
| **后置条件** | 交通状况改善，执行记录保存 |
| **数据速率需求** | 中等 |
| **时延需求** | ≤ 1 ms |
| **可靠性需求** | 99.99999% |
